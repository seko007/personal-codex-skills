# 再利用と保守

## 抽出方針

| 元資料の種類 | 残した内容 | 配置 |
| --- | --- | --- |
| 不具合調査・レビュー | 証拠、仕様整合、横断確認、失敗と復旧 | 各スキルと同梱資料 |
| バックエンド実装標準 | 境界、型、DB整合性、大量処理、差分整理 | 実装スキルの同梱資料 |
| 大量テーブルDDLメモ | DB条件に合う方式、負荷・ロック、照合・復旧 | 移行の安全確認 |
| 課題分析・対応表 | 前提、選択肢、影響、実装・回帰・移行ゲート | 分析・対応表スキル |
| 工数見積もり | 工程別の積み上げ、実績、仕様パターン、待ち時間 | 見積もりスキル |
| コミット文面 | 実差分、利用先の書式、実行許可の区別 | コミットメッセージスキル |
| 文書管理・SDD | 正本、今回の変更、過去履歴、承認段階 | 文書スキル、SDDガイドと雛形 |
| 個人共通指示・プロジェクト指示 | 丁寧な文体、判断材料、作業範囲、安全な実行 | 指示書の雛形 |
| フェーズ固有の機能調査 | 段階実装、API責務、実体と管理台帳の区別 | 分析スキルの同梱資料 |

業務固有の仕様書、個別課題・顧客・テーブル・本番データ、ローカル絶対パス、固定ブランチ、固定のインフラ構成は配布物へ持ち込みません。

特定モデルを毎回強制するルーティングや自動委譲は汎用スキルへ移植していません。モデルは利用環境で選び、対応モデル・推論強度・変更可能性を確認します。選択の推奨を、実際にモデルが変更されたという報告に置き換えないでください。

元の個人設定を継続的に公開フォルダへ同期する運用にはしません。追加・更新時は、再利用する判断・手順を抽出し、固有情報と依存関係を確認します。

## 配置の判断

- 呼び出す状況が明確な作業手順は `skills/`。
- 一つのスキルが必要時に読む資料は、そのスキルの `references/`。
- プロジェクトへ導入・編集して使う内容は `templates/`。
- 人が導入や運用の理由を理解する説明は `guides/`。
- 技術固有の規則は、汎用の必須ルールへ混ぜず、必要になったときに技術別のスキルや参考資料として切り出す。

単独インストールのため、スキルからパッケージ外の資料を必須参照させません。関連スキルへの言及は任意の補助とし、未導入の場合の進め方も記載します。

## 動作を確認する依頼例

| 依頼 | 期待する境界 |
| --- | --- |
| 「空文字でエラーになる原因を調べて」 | 調査結果と原因根拠を示し、診断だけで修正を開始しない |
| 「移行と再送を含む計画を作って」 | 母集団・残件照合、返却の同等性、復旧条件を具体化する |
| 「この差分をレビューして」 | 発生条件と影響のある指摘を先に示し、無断修正しない |
| 「仕様を確認するコメントを書いて」 | 背景と提案、選択肢と影響、判断事項を丁寧で自然な日本語にする |
| 「仕様が未確定なので見積もって」 | 案ごとの範囲と前提、工程別の概算、未決事項を示す |

これらは採用後の評価例です。構造検査の成功だけで、これらの実依頼に対する動作が検証済みと判断しないでください。
