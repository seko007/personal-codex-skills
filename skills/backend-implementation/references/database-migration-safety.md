# 移行の安全確認

## 設計・適用

変更前にDBの種類・実バージョン、対象環境、データ量、インデックス・参照関係、許容停止時間、適用と復旧の権限を確認する。読み取り確認と実行計画の検査にも、利用先の環境規約を使う。

スキーマ変更とデータ変換、空の新規環境と既存環境を分ける。初期データ定義やシーダーの変更だけで、既存環境へ反映されたと判断しない。

大量テーブルでは、変更の実行方式、走査・再構築、ロック、追加ディスク、実行時間を調べる。オンラインDDLやアルゴリズム指定の可否は、DBの実バージョン、テーブル条件、変更内容に対応する公式資料と検証結果で判断する。特定のアルゴリズムを全DDLへ一律に指定しない。

## データ変換

- 対象全体を抽出する条件、除外、重複・曖昧なデータの扱いを決める。
- ドライラン、対象件数、処理済み・拒否・残件の照合を用意する。空の入力を全体の移行完了と扱わない。
- 書き込み直前の再検証、並行更新、分割単位、再実行、部分失敗を考慮する。
- 新処理の実行開始と移行完了の順序、ガード、旧・新アプリの互換期間を決める。
- ロールバックでデータを失う場合は、逆マイグレーションを復旧手段とみなさず、バックアップ復元や前進修正の計画を示す。

## 実行

適用前に環境・対象・復旧手段を確認する。通常の未適用マイグレーション実行の許可から、全削除・再初期化の許可を推測しない。データを削除する操作は、対象と削除結果について明示的に許可を得る。

適用後はスキーマ・参照・件数・残件と、変更を利用する実際の経路を確認する。コマンドが終了したことと、受入条件を満たしたことを分けて報告する。
