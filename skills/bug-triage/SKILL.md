# Bug Triage

期待値と実際の挙動を分け、根拠のある診断と修正方針を返す。

1. 報告から、期待値、実際の挙動、対象環境、再現条件、発生頻度を整理する。欠けている情報は、安全な調査を進めながら絞り込む。
2. 利用先のプロジェクト規約、対象の現在仕様、関連コード・テスト・契約を確認する。過去の計画を現在仕様として扱わない。
3. 入力から保存・返却・副作用まで追い、条件を限定した再現確認またはコード上の根拠を集める。別の利用経路も同じ原因の影響を受けるか調べる。
4. 「再現済み」「コード上の根拠あり」「仮説」「未確認」を区別する。再現できていないことを、事象が存在しない証拠にしない。
5. 原因、影響、最小限の修正案、回帰確認を示す。期待挙動が未決なら、選択肢ごとの影響を説明し、人の判断へ切り出す。

原則としてチャットで回答し、報告書を求められた場合は指定先またはプロジェクトの文書配置ルールに従う。診断依頼ではコード修正を始めない。修正まで依頼されている場合は、既に得ている許可とプロジェクトの開始条件を確認して進める。

診断のために既存データを消去したり、外部へ実送信したりしない。実行する確認は利用先の開発環境で行い、実施した範囲と未確認範囲を明記する。
