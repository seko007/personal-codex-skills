# Pre-Implementation Matrix

仕様と実装と確認方法を対応させ、抜けや未決事項を実装前に可視化する。計画依頼だけで実装を始めない。既に実装許可がある場合は、同じ許可を繰り返し求めない。

## 手順

1. 利用先の規約、現在仕様、受入条件、契約、関連コードを確認する。プロジェクトの仕様承認段階が未完了なら、判断材料の整理に留める。
2. 確定要件と判断事項を分け、入力から保存・返却・副作用までの範囲を特定する。
3. 小さな実装単位と確認方法を列挙する。必要な行だけで [対応表の形式](references/matrix-forms.md) を使う。
4. DB・CSV・マスタを変更する場合は、新規初期化と既存環境反映を別行で扱う。
5. 状態、冪等性、競合、移行、外部副作用を扱う場合は [高リスク変更の確認](references/high-risk-gates.md) を読む。
6. 実際の開発環境に合う検証手順を示す。確認コマンド自体がデータ変更・実送信を起こすかを明示し、権限や環境を確認する。
7. 実装中は結果と状態を更新する。設計が変わる場合は、影響を受ける不変条件・失敗経路・復旧方法も更新する。

小さい変更はチャットの短い表でよい。文書作成が求められている場合は指定先か配置規約に従う。課題番号があるだけで作業記録を新規作成しない。

## 状態と完了

状態は `未着手 / 対応中 / 対応済み / 対象外 / 未確認` を使い、対象外と未確認には理由を添える。

業務上の期待結果、権限、状態遷移、削除、外部送信が未決な行は、その判断が必要な実装・テストの開始条件にする。実行時の検証が未実施な行は、必要な検証と完了条件を明示する。実装前に実装後の検証結果を要求するわけではない。

重要な照合・復旧・契約確認が残る場合は、完了やリリース可能と断定しない。別スキルのインストールや特定のフレームワークを前提としない。
