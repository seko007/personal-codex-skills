# 段階実装と責務

仕様が目指す完成形と、今回の実装範囲を分ける。関連APIが存在しないという理由だけで現在のコードを不具合と断定しない。

| 分類 | 判断の根拠 |
| --- | --- |
| 実装済みで整合 | 今回の受入条件と実装・確認結果が一致 |
| 今回の範囲で不足 | 今回担当する要件が実装されていない |
| 別の変更で実装予定 | 責務・担当・順序が確認できる |
| 仕様が競合・未確定 | 現在仕様と依頼・契約が一致しない、責務が不明 |

APIやジョブごとの責務を短い文で定義し、関連する処理の責務を一つの入口へ無条件に押し込まない。未実装の依存が今回の完了を妨げる場合は、その依存と切替条件を明示する。

ファイル機能では、メタデータ一覧、アップロード、ダウンロード、削除、履歴登録を区別する。一覧表示がダウンロード履歴を作るべきかは契約で判断する。

オブジェクトストレージの実体と、DBなどの管理台帳のどちらが各情報の正本かを確認する。更新者、版、可視性、監査情報が必要な一覧は、ストレージ内の名前だけでは成立しない場合がある。
