# 重要な確認条件

調査対象に関係する条件を選び、現状の根拠と判断が必要な挙動を分ける。

- 状態: 許可・禁止遷移、処理主体、失敗・タイムアウト後の復旧主体。
- 再実行: 同一・異なる入力の再送、初回と再送の返却値、副作用回数、コミット結果不明時の照合。
- 並行処理: 検証と書き込みの間の変更、重複防止、ロック、条件付き更新。
- 既存データ: 対象全体と除外、変換・初期化、件数・残件照合、切替順序。
- 外部副作用: コミットとの順序、重複、部分成功、再送・補償、利用者への案内。
- 契約: 認可・所属、null・空値、削除済みデータ、並び順、検索・一覧・CSV間の整合。

重要な期待結果が未決なら、人の判断へ切り出す。コード上の仕様を確認することと、新しい業務ルールを決めることを混同しない。

DB制約・スコープ・ジョブ設定など、実行環境で成り立つ必要がある条件は確認経路まで示す。未確認を「対応済み」と書かず、実装・リリースへの影響を示す。
